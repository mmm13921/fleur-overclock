# دستگاه، پلتفرم و سازگاری

## دستگاه هدف

- Redmi Note 11S 4G، codename: `fleur`
- SoC: MediaTek MT6781 / Helio G96
- GPU: Mali-G57 MC2
- CPU: 8 هسته؛ 6×Cortex-A55 و 2×Cortex-A76 (دو کلاستر)
- حافظهٔ RAM در دستگاه کاربر: 8GB
- بوت‌لودر/محیط کاربر: Android با root/Magisk در آزمایش‌های گزارش‌شده.

## خانواده‌های سورس

- سورس رسمی Xiaomi برای fleur در شاخه‌های قدیمی‌تر با Linux 4.14.x دیده شده است؛ در سوابق نسخه‌هایی مانند 4.14.186، 4.14.315 و 4.14.343 آمده‌اند. شمارهٔ دقیق باید از manifest همان build استخراج شود.
- Fleux V11 در پروژهٔ فعلی به Linux 4.19.325 اشاره دارد.
- تصمیم فعلی برای توسعهٔ آتی: Fleux V12 مبنای اصلی باشد. CIهای EEVDF که در این گزارش آمده‌اند هنوز ورودی Fleux V11 داشته‌اند؛ تغییر مبنا باید آگاهانه و با تطبیق config، defconfig، DTB، vendor modules و AnyKernel انجام شود.
- هدف‌های قدیمی MIUI/HyperOS و AOSP لزوماً ABI یا vendor compatibility یکسان ندارند. بوت موفق روی یک ROM، سازگاری با همهٔ ROMها را ثابت نمی‌کند.

## قواعد boot image و packaging

- device targeting در AnyKernel3 در سوابق: `fleur`، `miel` و `missi` به‌عنوان نام‌های سازگاری ذکر شده‌اند؛ هر نام باید با واقعیات boot/vendor همان build سنجیده شود.
- تجربهٔ قبلی: خطای AnyKernel «Unsupported device Aborting» رخ داده؛ پس قبل از انتشار، propertyهای device name و روش تشخیص دستگاه در AnyKernel باید با getpropهای واقعی ROM مطابقت داده شوند.
- ساختار boot مورد استفاده در پورت‌های قدیمی: header v2؛ DTB باید در محل درست boot image پچ شود و نباید صرفاً به Image.gz-dtb append شود، مگر قالب هدف صریحاً همین را بخواهد.
- cmdline، ramdisk، AVB و header نباید ناخواسته تغییر کنند.
- برای gzip از `gzip -9n` استفاده شده؛ خروجی Image و DTB باید مستقل validate شوند.
- فایل‌های اصلی boot/ramdisk کاربر را بدون درخواست صریح تغییر نده.

## CPU/GPU/نمایشگر — یافته‌های آزمایشی کاربر

این موارد گزارش‌های آزمایش هستند، نه تضمین پایداری عمومی:
- B-cluster تا 2055MHz با جدول OPP مشخص boot شده؛ فرکانس‌های بالاتر از این در بعضی buildها به تقسیم مؤثر فرکانس/خواندن مقدار نادرست منجر شده‌اند (برای نمونه 2197 به حدود 549MHz گزارش شده).
- CCI حدود 1850MHz و در برخی تست‌های 4.14 مقدار 1900MHz boot شده؛ 2000MHz boot نشده است.
- GPU Mali-G57 MC2 مقدار 1003MHz boot شده؛ تلاش‌های 1050/1100MHz بهبود عملکرد روانی نداشته و 1400MHz با 1.1V boot نشده است.
- نمایشگر 96Hz در یک build کاربر فعال و قابل استفاده گزارش شده است.
- تغییرات فرکانس/ولتاژ/thermal باید با OPP، PVT, DVFS, SSPM, SRAM, DTB, PPM و EEM هماهنگ باشند؛ تغییر صرف جدول OPP کافی نیست.
- کاربر در تست‌های عملکردی COD Mobile latency و FPS پایدار را بر مصرف باتری مقدم دانسته؛ بااین‌حال محدودیت‌های سخت‌افزاری و thermal safety را نباید با حذف کورکورانهٔ محافظ‌ها دور زد.

## ورودی‌های محیط کاربر

- ابزارهای توسعه عمدتاً GitHub Actions و گوشی/تبلت؛ دسترسی به PC محلی فرض نشود.
- خروجی نهایی موردنیاز معمولاً AnyKernel3 ZIP است، نه صرفاً Image.
