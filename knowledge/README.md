# Kernel Project Knowledge Base

این پوشه مرجع پایدار دانش پروژه است. هدف آن جلوگیری از تکرار خطاها و حفظ علت، راه‌حل و وضعیت تأییدشده هر تغییر است.

## قواعد ثبت دانش

- برای هر بیلد، یک گزارش در `builds/` با شناسه یا نام بیلد ایجاد/به‌روزرسانی شود.
- هر خطا با این موارد ثبت شود: مرحله، پیام/نماد خطا، علت ریشه‌ای، فایل و commit اصلاح، نتیجهٔ بیلد بعدی.
- «Audit موفق»، «کامپایل موفق»، «بسته‌بندی AnyKernel موفق» و «بوت/تست روی دستگاه» چهار وضعیت مستقل‌اند؛ هرگز یکی را معادل دیگری ثبت نکنید.
- قبل از پچ جدید، این پوشه و گزارش‌های بیلدهای قبلی بررسی شوند.
- راه‌حل‌های موقت یا حدسی باید صریحاً با وضعیت «تأییدنشده» مشخص شوند.
- تغییرات حساس به دادهٔ کاربر، FBE/fscrypt، F2FS و FUSE نباید بدون شواهد و بررسی رگرسیون انجام شوند.
