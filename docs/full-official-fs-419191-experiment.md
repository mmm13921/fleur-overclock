# Full official Linux 4.19.191 filesystem experiment

Target: Redmi Note 11S 4G / POCO M4 Pro 4G (fleur, MT6781).

This is an isolated experiment based on Fleux Linux 4.19.325. It replaces the complete `fs/` directory with the official Xiaomi MT6781 Linux 4.19.191 `fs/` tree pinned to commit `6f6b84e0e2fa8d474db66798a051ec1835257729`. The matching official `include/linux/f2fs_fs.h` and `include/trace/events/f2fs.h` are also copied so the F2FS on-disk and trace definitions stay aligned with that donor.

The replacement includes VFS core files, mount/remount handling, F2FS, EXT4, FUSE, OverlayFS, FAT-family filesystems, and the other files under `fs/`. In the official 4.19.191 donor, EROFS still lives under `drivers/staging/erofs`, not under `fs/erofs`; the experiment therefore also imports that complete official EROFS source tree, its `include/trace/events/erofs.h` header, and merges only the EROFS Kconfig/Makefile registration lines into Fleux's existing staging files. Imported EROFS files are byte-verified against the pinned donor. It deliberately does not merge Fleux's newer filesystem-specific changes back into the replaced `fs/` directory. The MT6781 DPMAIF suspend/resume guard is in `drivers/` and is kept separately. Because replacing all of `fs/` also removes Fleux's SUSFS core, the experiment keeps the dedicated `fs/susfs.c` implementation and its `obj-$(CONFIG_KSU_SUSFS) += susfs.o` Makefile entry, together with the unchanged `include/linux/susfs.h` v2.3.0 header. The donor's two EXT4 fault callbacks are also adapted in `fs/ext4/inode.c`, and their declarations in `fs/ext4/ext4.h` are updated to return `vm_fault_t`, matching the Fleux 4.19.325 MM callback API. The two EXT4 `__vmalloc()` calls in `fs/ext4/super.c` are also adapted from the old three-argument form to the two-argument Fleux API. EXT4's old `e_reusable` field accesses in `fs/ext4/xattr.c` are mapped to the newer `MBE_REUSABLE_B` flag in `mb_cache_entry.e_flags` using `set_bit()`, `test_bit()`, and `clear_bit()`. The original 4.19.191 files are byte-verified before these explicit compatibility overlays are applied.  Fleux's complete `fs/kernfs/` subtree is preserved and audited against its packed `u64` kernfs ID (`generation:ino`) and xattr APIs. The Fleux `fs/nsfs.c` namespace pseudo-filesystem is also retained because its `ns_get_path()` API returns `int`, unlike the donor's pointer-returning implementation; the imported `fs/proc/namespaces.c` caller is adapted to that Fleux contract. Fleux's four-argument `do_faccessat()`, `faccessat2` wrapper, and matching private `filename_lookup()` declaration are also restored together so the SUSFS access hook matches the 4.19.325 syscall ABI. The imported legacy VFS mount path in `fs/super.c` is also adapted to Fleux's 4.19.325 interfaces: vendor-only `mount2`/`remount_fs2` callbacks are removed in favor of the existing `mount`/`remount_fs` callbacks, and legacy LSM mount-option handling is translated to `security_sb_eat_lsm_opts()`, `security_sb_set_mnt_opts()`, `security_sb_kern_mount()`, and `security_free_mnt_opts()`. This preserves SELinux option extraction/application without adding stale vendor-only members to Fleux's `struct file_system_type` or `struct super_operations`. The FUSE inode also receives a local `VM_MAX_READAHEAD=128` KiB fallback because Fleux 4.19.325 no longer exports that legacy MM macro; this preserves the official FUSE readahead limit without changing the global MM header. It then reapplies only the four FleuxSU inline-hook sites required by its build-time checker: `ksu_handle_execveat`, `ksu_handle_faccessat`, `ksu_handle_sys_read`, and `ksu_handle_stat`. Their source locations and SUSFS guards are checked by the post-build audit; VFS/F2FS and the other filesystem implementation files remain from the pinned Xiaomi donor.

## Important compatibility impact

This creates a mixed-version kernel: Fleux 4.19.325 outside `fs/`, with the official 4.19.191 implementation inside `fs/`. The official donor predates Fleux's newer `fs_context` VFS path and filesystem-specific KernelSU/Fleux changes. The complete `fs/kernfs/` subtree is deliberately retained from Fleux 4.19.325 because the donor implementation is incompatible with the Fleux `include/linux/kernfs.h` packed-u64 node ID and newer xattr APIs; kernfs is a shared pseudo-filesystem subsystem, not the Android userdata filesystem. Fleux's `fs/nsfs.c` is also retained to match the `int ns_get_path()` declaration in `include/linux/proc_ns.h`; the donor's `fs/proc/namespaces.c` is narrowly adapted to consume that return code and return `ERR_PTR(error)` as required by the procfs link callback. The Fleux four-argument `do_faccessat()` implementation and `faccessat2` wrapper are restored, and `fs/internal.h` receives the corresponding `filename_lookup()` declaration. Its donor definition in `fs/namei.c` is changed from `static` to external linkage, matching Fleux's exported helper so the call from `fs/open.c` links correctly. Replacing the tree may therefore cause compile/link incompatibilities or remove filesystem-side hooks. The build is intentionally isolated on this branch and published only as a prerelease candidate.

The workflow must pass source-tree identity checks, compile the full kernel, verify the gzip kernel plus appended DTB, and validate the AnyKernel3 ZIP before publishing. A successful CI build still cannot establish that HyperOS can mount and decrypt real `/data`, access all existing files, preserve app data, or behave correctly across reboot and suspend/resume.

Do not overwrite the known-good kernel or remove the recovery path. Flash only after the image is built successfully and keep the previous boot image available. If the phone cannot mount userdata or reports filesystem errors, restore the known-good boot image; do not format userdata.


### NLS API compatibility

The imported NLS implementation is adapted to Fleux's `load_nls(const char *)` declaration by changing both `find_nls` and `load_nls` definitions to const-correct signatures.

### Legacy VFS mount API compatibility

The Xiaomi `fs/super.c` donor uses `mount2` and `remount_fs2` callback members plus the older `alloc_secdata()` / `security_sb_copy_data()` / three-argument `security_sb_kern_mount()` LSM API. Those members and helpers are not present in Fleux 4.19.325. The compatibility layer therefore keeps the donor's legacy `mount_fs()` and `do_remount_sb2()` flow but dispatches through Fleux's regular `mount` and `remount_fs` callbacks. SELinux mount options are extracted and applied using the current `security_sb_eat_lsm_opts()` and `security_sb_set_mnt_opts()` interfaces, followed by the current `security_sb_kern_mount()` permission hook, and released with `security_free_mnt_opts()`. A post-build source audit checks that no obsolete vendor-only callback or LSM helper remains in `fs/super.c`.

### procfs VMA soft-dirty API compatibility

The official 4.19.191 `fs/proc/task_mmu.c` wraps the `VM_SOFTDIRTY` VMA-flag update in `vm_write_begin()` and `vm_write_end()`, which rely on `vm_sequence` in `struct vm_area_struct`. Fleux 4.19.325 does not provide that VMA field or those helper functions. The compatibility overlay therefore ports only this `clear_refs_write()` loop to the exact Fleux implementation: clear `VM_SOFTDIRTY` and refresh `vm_page_prot` while holding the existing `mmap_write_lock`. It does not add an incomplete seqcount ABI to the Fleux MM structures.
